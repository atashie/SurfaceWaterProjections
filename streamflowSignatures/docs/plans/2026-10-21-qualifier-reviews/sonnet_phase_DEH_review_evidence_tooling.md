State this in the plan/CHANGELOG, or run the stage censuses with the ledgers.
M2. **stage_attribution.py does not implement the third promised identity.** The docstring (lines 11-12, 21) and plan §10.4 say "S0 = S2 on class U (both layers)"; the code computes `U = ...` (line ~85) and never uses it. The identity is in fact covered by the census gates "class U identical (annual / summary)" and 5e (verified above by me), so no substantive gap — but fix the docstring or the code.
M3. **"validated by 5c" is not true for the one withdrawn key.** assess_rerun_changes.py new branch (diff hunk after the `qp` withdrawal rule): 5c recomputes only values present in the new file, so a lost key cannot be validated by it. I verified the single case by hand: 05527500 elasticity_annual WY2018, A-J gage, Qann unchanged, prcp_annual WY2017 moved 1036.5 -> 1059.68 so |P2018 - P2017| = 0.077 < min_dP 0.1 (julia/src/elasticity.jl:130, 206), so the year-over-year key is correctly dropped. Mechanism genuine; relabel the string (the code could test the |dP| threshold directly, as it does for the recession and Q-P gates).
M4. **Record-dependent "key emitted / withdrawn on an old year" is a catch-all.** Condition: `d_ == "record_dependent" and (class in A-Q/A-QJ if Q_only else class != "U")`. Any emitted key on any non-U gage whose signature is record-dependent is explained, without a per-cell mechanism check. Realised use is small: 111 + 4 emitted (BFI_Eckhardt_param 46, BFI_LyneHollick_param 46, elasticity_annual 4+1, elasticity_rolling 15+3 across 20 gages) and 1 withdrawn. Mitigation that makes this acceptable: E7 compares annual KEY SETS of all 1,609 / 1,356 affected gages between Julia and the independent Python port and found them identical (e7_annual.txt "[2] key sets ... identical", NA patterns identical), so each emitted key is reproduced independently. Residual risk is a common-mode emission shared by both languages (parametrised-BFI fit success, elasticity dP threshold) — no evidence of it.
M5. **Qann fallback (question B-iii): not weaker in effect, but weaker in kind.** For the 5,069 / 4,894 non-replayed gages the valid-year sets now come from the output's own Qann keys (old and new) instead of the independent state tables. Check 5f then compares the oracle's baseline = final sets with outputs that are identical by construction. What protects it: (a) 5e + class-U gates are full cell-for-cell identity on exactly those gages (I reproduced 0 differences at both layers), (b) the oracle says no gage outside the 1,609 / 1,356 non-U has a gained year or a restored day (verified above), (c) the fallback is applied only to gages absent from the state tables, and the total_possible gate now asserts every absent gage is class U. Residual: class membership of "not replayed" is itself derived from the manifest; an affected gage missing from the manifest would be classed U on Qann keys alone and then caught only by the oracle-vs-census gained-years check (5d, passes) — acceptable.
M6. **Scoped total_possible freeze (B-iv).** Compares 1,609 replayed gages (0 differ) and asserts the rest are class U. `total_possible` is not in the summary CSV, so for the 5,069 non-replayed gages it is not directly compared anywhere; num_water_years / start / end (which are) are identical on them. Low risk (the spliced input only touches affected gages), but the assertion rests on the class label, not on a measured comparison of the gage tables. Could be closed by comparing metadata/gage_S0 for all gages cheaply.
M7. **Over-tolerance E7 cells are caught on an absolute 1e-9 gate.** 49 / 54 of the 117 / 188 are elasticity_annual and qp_slope_sd float noise (relative 1e-11); listing them among "documented residual signatures" with an `allow_value_diff` equal to the observed count (117, 188) is fine but tuned; a relative tolerance for those two signatures would be more honest than allowing 19 signature names in total (allow_diff_signature includes whole families, e.g. D1_day..D99_day, that only exhibit ±1 day).

### NOTE
N1. --allow-gate-state-column (B-ii): the check recomputes the 16 statistics with the PYTHON port's generate_stats from EACH side's own annual series (check_summary_equality.py:67-104) and accepts the NaN-vs-finite cell only if the pair is tie-bearing, the column matches the regex, and BOTH sides' recomputed values reproduce the stored cells within rtol/atol (lines added at ~213-230). It cannot accept a cell whose recomputation is missing (`continue`). It does not weaken the gate for any other column: the regex (FDC90th|FDCmid rank/Pettitt columns) is identical to the existing waive-column regex and must be accepted by name downstream (accepted in the census: waivers listed, unaccepted []). Realised use: 8 / 7 cells, all FDC90th on 3-4 gages (15896000, 02304500, 02313230, 401733105392404), displayed in e7_summary.txt. Caveat: the Julia (reference) NaN is "reproduced" by the Python implementation applied to Julia's series — circular for the Julia statistic itself, so it shows the annual series differ at the tie level, not that Julia's gate state is right. One of the delivered cells (Julia NaN vs Python finite, e.g. 15896000 FDC90th_mk_pval) is therefore a zero-heavy tie ambiguity in the DELIVERED product; the Known-Issue text should say which side is delivered.
N2. preprocess_state_ledger.py check 2 patch: the new expectation (a climate NA day in a year where that variable is invalid stays NaN) matches julia/src/io.jl lines ~473-508 (interpolation and write-back happen only `if ppt_ok`; same pattern for SWE/temperature). The patch fixes a verification defect, does not relax a production gate. Because the expectation now depends on the variable's own validity flag, a wrong validity flag would no longer be caught by this check; it is checked by other state-table gates.
N3. check_annual_parquet_equality.py --gages: restricts BOTH sides; fails if a listed gage is absent from both sides; the E7 JSON records the file and count, and the census binds it by sha256 and checks the compared gages cover the affected manifest ("compared gages 1609 cover the 1609 affected gages: True"). Does not weaken a gate. A listed gage missing on one side only is still caught by the key-set check.
N4. Interaction residual (question C): meaningful and plausibly non-additive by construction. 2,650 of 656,930 cells outside tolerance; 2,329 are elasticity_annual (107 gages) and 292 elasticity_rolling; all outside-tolerance cells lie on the `overlap` (2,284 cells) and `restored_with_inserted` (356) members; none on the eligibility / dec31 gages. Elasticity uses record-wide Q_mean / P_mean and year-to-year differences with a |dP| > 0.1 threshold, so a Q change and a P change interact multiplicatively (cross term) and via pairing of consecutive valid years. Of the 2,329 elasticity_annual cells 2,011 sit on overlap gages and all have BOTH a non-zero splice effect and a non-zero join effect. The other families (runoff ratios, qp_*) show <= 7 cells because their annual values change only when the same year is touched by both effects, and such years are gained keys (excluded from the four-stage comparison; 88,004 keys are absent from at least one stage). One wording error: plan §11 explains the elasticity residual as "a year gained by the splice that also carries inserted climate days", but gained keys are excluded from the residual by construction; the mechanism for the 2,650 shared-key cells is the record-wide mean and neighbour dependence. avg_storage 3 cells (max 1.3) is the same kind (storage depends on both Q and P records).
N5. Identities (question C): control 200 and join-only 197 / 199 are real tests, executed on both sides cell for cell (455,200 summary cells, 833,690 annual rows; 448,372 cells, 813,718 rows). They test the specific design claims "the splice alone changes nothing on a gage without a restored day" and "the join alone equals the full fix on a gage without splice rows". They are samples (200 of 5,069 untouched-by-splice is fine; 197 of 710 A-J gages = 28 %), and the 3 / 1 sampled join-only gages inside the interaction cohort are correctly excluded (`join_only = s1p_gages - interaction`). The full-cohort S1 for 5,579 / 5,293 gages is INFERRED from S0 and labelled so. The remaining 513 A-J gages are covered only by the input-level fact that no spliced row exists for them (and by the census 5a "Q-only summary columns identical on join-only gages", PASS).
N6. The E7 summary gate leaves 8 / 7 gate-state cells, 1,510 / 2,503 tie-sensitive and 472 / 775 propagated-residual cells "reported" rather than gated; these counts are in the JSON and the CHANGELOG ("0 gated") — consistent.
